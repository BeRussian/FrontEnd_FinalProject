💡 מילון מושגי היסוד (מאפס ועד מתכנת בכיר)
כל מושג שמופיע בקוד, עם הסבר פשוט, דוגמת קוד מהפרויקט, ולמה הוא נבחר.
1. מה זה Single Page Application (SPA)? ▼
הסבר פשוט: באפליקציית אתר מסורתית (MPA), כל לחיצה על קישור שולחת בקשה לשרת, הדפדפן מרענן את כל העמוד בלבן וטוען קובץ HTML חדש.
ב-SPA (כמו EasyBite עם React Router), יש רק קובץ HTML אחד (index.html). כשמשתמש לוחץ על קישור, JavaScript מחליף בזיכרון רק את החלק הרלוונטי בעמוד בלי שום רענון מסך! המעבר מהיר ברמת מילי-שניות ונראה כמו אפליקציית Native לטלפון.
2. למה השתמשנו ב-TypeScript קפדני ואסרנו על שימוש ב-any? ▼
הסבר פשוט: any ב-TypeScript הוא פקודה שאומרת לקומפיילר: "אל תבדוק אותי, תתעלם מבאגים". שימוש ב-any מבטל את כל הפואנטה של TypeScript וגורם לשגיאות זמן-ריצה מביכות.
ב-EasyBite הגדרנו Interface מדויק בשם Recipe ב-src/types/recipe.ts. כל שדה (כותרת, מרכיבים, תמונה) מוגדר כ-string או string[]. הקומפיילר (tsc -b) בודק כל שורה בזמן הבנייה ומוודא ב-100% שאין טעויות כתיב או ערכים חסרים.
3. תבנית ה-Master-Detail והתגית <Outlet /> ▼
הסבר פשוט: Master-Detail היא תבנית שבה בצד אחד מוצגת רשימת כל הפריטים (Master), ובצד השני מוצג הפריט שנבחר בהרחבה (Detail).
ב-React Router, התגית <Outlet /> משמשת כ-"מקום שמור" (Placeholder) בתוך קומפוננטת האב (CatalogPage). כשהמשתמש גולש ל-/recipes/52772, ה-Outlet טוען לתוכו אוטומטית את קומפוננטת RecipeDetailPage, בעוד סרגל הצד נשאר מקובע במקומו.
4. שליפת פרמטר דינמי עם useParams() ▼
הסבר פשוט: כשהנתיב מוגדר בראוטר כ-path="recipes/:id", הנקודתיים מסמנות ש-id הוא משתנה דינמי.
בקומפוננטת RecipeDetailPage, אנחנו מפעילים את ה-Hook: 
const { id } = useParams<{ id: string }>();
הוא שולף מתוך כתובת ה-URL את המספר המדויק ומאפשר לנו למצוא את המתכון במערך: recipes.find(r => r.id === id).
5. למה Derived State עם useMemo עדיף על useState כפול? ▼
שאלת מפתח בהגנה: מתחילים נוטים ליצור filteredRecipes בתוך useState נפרד, ואז צריכים לזכור לעדכן אותו ב-useEffect בכל פעם שהמשתמש מקליד אות או כשהנתונים מגיעים מה-API. זה מוביל לבאגים קשים של חוסר סנכרון!
הפתרון המקצועי שלנו: שומרים ב-State רק את מחרוזת החיפוש (searchQuery), ומחשבים את הרשימה המסוננת כ-Derived State בזמן אמת: 
const filteredRecipes = useMemo(() => {
  return filterRecipes(recipes, searchQuery, selectedCategory);
}, [recipes, searchQuery, selectedCategory]);
המידע מחושב מחדש אך ורק כשאחד המשתנים משתנה, ותמיד מובטח סנכרון מושלם ב-100%.
6. רכיב מבוקר (Controlled Component) ▼
הסבר פשוט: בשורת החיפוש SearchBar, תגית ה-<input> אינה שומרת את הטקסט בעצמה, אלא מקבלת את הערך מה-State: value={searchQuery}.
בכל הקלדת תו, אירוע ה-onChange מפעיל פונקציה שמעדכנת את ה-State של React, וה-State מזין בחזרה את ה-Input. React הוא מקור האמת היחיד לכל אות שמוקלדת.
7. מניעת בעבוע אירועים (Event Bubbling & stopPropagation) ▼
הסבר פשוט: כרטיסיית מתכון בסרגל היא תגית קישור <NavLink to="...">. בתוכה נמצא כפתור כוכב המועדפים.
ב-DOM, כשלוחצים על אלמנט פנימי, האירוע "מבעבע" (Bubbles) כלפי מעלה לאלמנטים העוטפים אותו. אם לא היינו עוצרים זאת, לחיצה על הכוכב הייתה גם מוסיפה למועדפים וגם מנווטת את המשתמש לעמוד אחר!
באמצעות הפעלת e.stopPropagation() ו-e.preventDefault(), עצרנו את הבעבוע והשארנו את הניווט יציב.
8. אתחול עצל (Lazy Initialization) בשמירה ל-localStorage ▼
הסבר פשוט: קריאה מ-localStorage דורשת גישה לדיסק של המחשב וביצוע JSON.parse. אם נכתוב: 
useState(JSON.parse(localStorage.getItem('favs') || '[]'))
הקוד הזה ירוץ ויבזבז משאבים בכל רינדור מחדש של הקומפוננטה!
במקום זאת, העברנו פונקציה: 
useState(() => JSON.parse(localStorage.getItem('favs') || '[]'))
בזכות זה, React מריץ את הקריאה מהדיסק אך ורק פעם אחת בלבד בעליית האפליקציה (Mount).
9. פירמידת הבדיקות: Unit, Integration, E2E ▼
1. Unit Tests (32 בדיקות): בדיקת פונקציות טהורות ומבודדות ב-Vitest (למשל filterRecipes, getRandomRecipe, הדמיית נפילת רשת HTTP 500). רץ תוך מילי-שניות ללא DOM.
2. Integration Tests (30 בדיקות): בדיקת רכיבי React שלמים עם @testing-library/react ו-jsdom. מדמה משתמש אמיתי שמקליד בשורת החיפוש, לוחץ על כפתור הניקוי, מסמן צ'קבוקס ברשימת הקניות או לוחץ על כוכב.
3. E2E Tests: בדיקת זרימת משתמש מקצה לקצה בדפדפן ממשי עם מנוע כמו Playwright.

src/services/recipeApi.ts — מתאם ה-API ושליפת הנתונים

הקוד שמושך 25 מתכונים מ-TheMealDB API, ממיר את המבנה השטוח למערך נקי ומטופס, ותופס נפילות רשת. 

// Adapter Pattern: ממיר את ה-20 שדות של MealDB למערך ingredients נקי
export const mapMealDBToRecipe = (meal: any): Recipe => {
  const ingredients: string[] = [];
  for (let i = 1; i <= 20; i++) {
    const ingredient = meal[`strIngredient${i}`];
    const measure = meal[`strMeasure${i}`];
    if (ingredient && ingredient.trim()) {
      ingredients.push(measure ? `${measure.trim()} ${ingredient.trim()}` : ingredient.trim());
    }
  }

  return {
    id: meal.idMeal,
    title: meal.strMeal,
    category: meal.strCategory || 'General',
    image: meal.strMealThumb || DEFAULT_RECIPE_IMAGE,
    prepTime: '15 mins',
    difficulty: 'Level 1',
    description: meal.strInstructions.slice(0, 120) + '...',
    ingredients,
    instructions: meal.strInstructions.split('\\r\\n').filter(Boolean)
  };
};

רשימת התרחישים הבעייתיים ביותר בפיתוח ווב ואיך נטרלנו כל אחד מהם מראש:
1. מזהה מתכון שלא קיים ב-URL (/recipes/999999) נפתר ✓
קוד רשלני קורס עם Cannot read property of undefined. אצלנו ב-RecipeDetailPage, אם !recipe, מרונדר מסך ייעודי ומעוצב עם כותרת "Recipe Not Found" בלי שום קריסה.
2. קישור תמונה שבור (Error 404 בתמונה) נפתר ✓
בכל תגית <img> מחובר מאזין onError שמחליף מיידית את מקור התמונה ל-DEFAULT_RECIPE_IMAGE ומאפס את ה-handler כדי למנוע לולאת שגיאות אינסופית.
3. חיפוש עם רווחים בלבד (" ") נפתר ✓
פונקציית filterRecipes מפעילה trim() על המחרוזת. אם התוצאה ריקה, היא מחזירה מיד את כל המתכונים בלי לסנן דבר.
4. זיכרון localStorage פגום או גלישה בסתר נפתר ✓
קריאות ה-JSON.parse עטופות ב-try/catch ומאמתות Array.isArray(). במקרה של שגיאה או חסימת דפדפן, המערכת חוזרת למערך ריק בבטחה. נבדק בטסט ב-useFavorites.test.ts.
5. הגרלת אותו מתכון פעמיים ברציפות נפתר ✓
ב-RandomRecipePage, פונקציית הגלגול החוזר מסננת את המנה הנוכחית (r.id !== currentRecipe.id) לפני שהיא מגרילה אינדקס אקראי, מה שמבטיח מתכון חדש בכל לחיצה.
6. דליפת זיכרון מטיימר Toast נפתר ✓
ב-useFavorites, האפקט שמנהל את ה-Toast מחזיר פונקציית Cleanup נקייה: return () => clearTimeout(timer). אם הרכיב יורד או מגיעה הודעה חדשה, הטיימר הישן מתבטל מיד.
