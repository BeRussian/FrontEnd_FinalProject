# תוכנית בדיקות יחידה: EasyBite (docs/testing.md)

> 🧪 **אסטרטגיית בדיקות ממוקדת ופשוטה (Vitest):**  
> לפי דרישות המרצה יריב גלעד, נדרשות לפחות **5 בדיקות יחידה** שבודקות לוגיקה אמיתית של האפליקציה (ולא דברים טריוויאליים כמו `1 + 1 = 2`), הניתנות להרצה בטרמינל (`npm test`) ובדפדפן באמצעות Vitest UI (`npm run test:ui`).

---

## 1. למה לבדוק פונקציות לוגיקה טהורות (Pure Functions)?
הדרך הפשוטה, הנקייה והקלה ביותר להסבר בהגנה היא בדיקת **פונקציות עזר טהורות** (Pure Utility Functions):
- פונקציה טהורה מקבלת קלט (למשל: רשימת מתכונים ומילת חיפוש) ומחזירה תמיד פלט צפוי.
- אין צורך בספריות כבדות שמדמות דפדפן (DOM mocking מסובך).
- הבדיקות רצות בשבריר שנייה, קריאות להפליא, וקל להסביר אותן ב-2 משפטים לבוחן.

---

## 2. חמש בדיקות היחידה המתוכננות (Vitest)

### בדיקה 1: סינון מתכונים לפי טקסט חיפוש (`filterRecipes by search query`)
- **מה בודקים:** כשמעבירים לרשימה מילת חיפוש (למשל `"egg"`), הפונקציה מחזירה רק מתכונים שבשם שלהם או במצרכים שלהם מופיעה המילה `"egg"`.
- **מקרה קצה:** בדיקה שהחיפוש אינו רגיש לאותיות גדולות/קטנות (Case-Insensitive), למשל חיפוש `"EGG"` ימצא מתכון עם `"egg"`.
- **ציפייה (Assertion):** מספר התוצאות תואם בדיוק למתכונים הרלוונטיים.

---

### בדיקה 2: סינון מתכונים לפי קטגוריה (`filterRecipes by category`)
- **מה בודקים:** כשבוחרים קטגוריה ספציפית (למשל `"Pasta"`), מוחזרים אך ורק מתכונים המשויכים לקטגוריית הפסטה.
- **מקרה קצה:** בחירת קטגוריה `"All"` מחזירה את כל המתכונים ללא סינון.
- **ציפייה (Assertion):** כל מתכון במערך המוחזר מכיל `category === "Pasta"`.

---

### בדיקה 3: בחירת מתכון אקראי מתוך רשימה (`getRandomRecipe`)
- **מה בודקים:** הפונקציה שמגרילה מתכון עבור עמוד "What Should I Make?" אכן מחזירה מתכון תקין שקיים בתוך המערך המקורי.
- **מקרה קצה:** אם מועבר מערך ריק של מתכונים, הפונקציה מחזירה `null` בצורה בטוחה ולא קורסת.
- **ציפייה (Assertion):** המתכון שהוגרל מכיל `id` תקף שנמצא ברשימת המתכונים.

---

### בדיקה 4: חילוץ וריכוז מצרכים לרשימת קניות (`extractShoppingList`)
- **מה בודקים:** כשמעבירים רשימת מתכונים מועדפים, הפונקציה מחלצת את כל המצרכים לרשימה אחת שטוחה ומסודרת ללא מצרכים ריקים.
- **מקרה קצה:** איחוד מצרכים כפולים או ניקוי רווחים מיותרים.
- **ציפייה (Assertion):** רשימת המצרכים מכילה את כל הפריטים הדרושים מהמתכונים שנבחרו.

---

### בדיקה 5: ניהול מזהי מועדפים ומניעת כפילויות (`toggleFavoriteId`)
- **מה בודקים:** 
  1. לחיצה על מתכון שאינו מועדף – מוסיפה את ה-`id` שלו למערך.
  2. לחיצה חוזרת על מתכון שכבר מועדף – מסירה את ה-`id` שלו מהמערך.
- **מקרה קצה:** מוודאים שאף פעם לא נוצרת כפילות של אותו `id` במערך המועדפים.
- **ציפייה (Assertion):** גודל המערך משתנה בהתאם (פעם גדל ב-1 ופעם קטן ב-1).

---

## 3. איך מריצים את הבדיקות?

1. **הרצה מהירה בטרמינל:**
   ```bash
   npm test
   ```
2. **הרצה ויזואלית בדפדפן (Vitest UI):**
   ```bash
   npm run test:ui
   ```
   הדפדפן נפתח בממשק גרפי המציג את כל 5 הבדיקות בירוק (Passed).
